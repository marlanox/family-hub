# Family Hub

Наша семья — общие задачи, баллы, награды и напоминания. Mobile-first PWA,
без ролей «админ/участник» — у всех одинаковые права. Подробности
архитектуры: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Запуск локально

```bash
npm install
npm run dev
```

Откройте http://localhost:3000 — при первом запуске приложение спросит,
как вас зовут, и предложит добавить остальных членов семьи. Ничего
дополнительно настраивать не нужно: данные хранятся прямо в браузере
(localStorage), офлайн и бесплатно.

## Установка как приложение (PWA)

1. Откройте задеплойенную ссылку (см. ниже) на телефоне.
2. В Safari (iPhone): «Поделиться» → «На экран «Домой»».
   В Chrome (Android): меню → «Установить приложение» / «Добавить на
   главный экран».
3. Готово — иконка на рабочем столе, открывается как обычное приложение,
   работает офлайн.

**Обновления.** Это веб-приложение — новую версию не нужно переустанавливать,
она приходит на ту же ссылку. Просто закройте и заново откройте приложение.
**Не удаляйте и не переустанавливайте иконку с домашнего экрана** — на iPhone
это может стереть локально сохранённые данные (если синхронизация не
включена, это единственная копия).

**Про хранение данных по умолчанию.** У каждого члена семьи данные хранятся
отдельно на его телефоне — баллы и задачи не синхронизируются между
устройствами, пока не подключите Supabase (ниже). Это осознанный выбор: так
приложение работает сразу, бесплатно и без сервера, которым нужно управлять.

## Деплой бесплатно

Этот репозиторий уже настроен под GitHub Pages (`npm run build:pages`,
см. `next.config.js`) — `git push` в ветку `gh-pages` со свежей сборкой, и
сайт живёт на `https://<username>.github.io/<repo>/`. Подойдёт и любой
другой статический хостинг ([Vercel](https://vercel.com), Netlify,
Cloudflare Pages) — тогда собирайте через обычный `npm run build`
(без `DEPLOY_TARGET=github-pages`).

## Хотите такую же копию для своей компании? (форк)

Код открытый — можно взять `git clone`/fork этого репозитория, завести
**свой** бесплатный Supabase-проект (шаги ниже) и задеплоить свою копию под
своей ссылкой. Так у каждой семьи — полностью отдельное бесплатное облако,
никто ни к кому в данные не попадает.

Более простой путь для друзей, которым не хочется форкать репозиторий:
открыть **ту же самую** ссылку на приложение, завести свой бесплатный
Supabase-проект и вписать его URL + anon key в **Настройки → Своё облако** —
тогда их семья хранится в их собственном Supabase, хотя само приложение
общее. Это настройка на их устройстве (localStorage), она никуда не
отправляется и не видна вам — и это единственный способ включить
синхронизацию: приложение никогда не пытается использовать чужой,
заранее подключённый облачный проект (даже тот, с которым его когда-то
собирали) — только тот, что человек сам вписал на своём телефоне.

## Синхронизация между телефонами семьи (опционально)

Чтобы баллы и задачи видели все на своих устройствах, нужен общий "облачный"
источник данных — без этого никак, но он не обязан быть платным сервером,
которым управляете вы. Бесплатный уровень [Supabase](https://supabase.com)
(Postgres + Storage + Edge Functions) полностью бесплатен для проекта
такого размера, без карты и без входа через что-либо, кроме email.

1. Создайте проект на supabase.com (бесплатно, только email).
2. В **SQL Editor** выполните целиком файл `supabase/schema.sql` — это
   создаст таблицы, функции и политики доступа (у всех членов семьи
   одинаковые права на данные своей семьи, ролей нет; тот же файл создаёт
   и bucket для фото).
3. Скопируйте **Project URL** и **anon public key** из **Settings → API**.
4. В приложении: **Настройки → Своё облако** → впишите эти два значения →
   «Сохранить». Пересобирать и переразворачивать ничего не нужно — это
   настройка конкретного устройства, хранится в его localStorage.
   (Supabase-ключи в `.env.local`/`NEXT_PUBLIC_SUPABASE_*` при сборке
   больше ни на что не влияют — приложение их сознательно игнорирует, чтобы
   ни у кого не было соблазна оставить одно общее облако на всех.)
5. В приложении: **Настройки → Синхронизация между телефонами** →
   «Создать код синхронизации» на одном телефоне, «Присоединиться по коду»
   на остальных.

Без своего Supabase-проекта, вписанного в «Своё облако», приложение
продолжает работать локально — ничего не ломается, синхронизация просто
выключена, и создать код или присоединиться по коду будет нельзя.

### Push-уведомления (кто-то выполнил/отменил задачу → остальные узнают)

Работает поверх синхронизации выше, нужен ещё один бесплатный шаг —
Supabase Edge Function, которая реально рассылает уведомления:

1. Сгенерируйте пару VAPID-ключей (один раз, локально, ничего никуда не
   отправляется): `npx web-push generate-vapid-keys`.
2. Публичный ключ добавьте как `NEXT_PUBLIC_VAPID_PUBLIC_KEY` (см. выше).
3. В Supabase Dashboard → **Edge Functions** → создайте функцию с именем
   `send-push`, вставьте туда код из
   `supabase/functions/send-push/index.ts` → Deploy.
4. Там же → **Secrets** (или Project Settings → Edge Functions) добавьте
   `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` (из шага 1).
   `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам.
5. В приложении: **Настройки → Уведомления на этот телефон** → включить
   (на каждом телефоне отдельно; на iPhone — только если приложение
   установлено на домашний экран, и на iOS 16.4+).

Это покрывает «кто-то отметил задачу → остальные получили пуш». Напоминание
«пора делать задачу» в заданное время — отдельная, ещё не собранная часть
(нужен планировщик; см. `docs/ARCHITECTURE.md`).

## Скрипты

- `npm run dev` — режим разработки
- `npm run build` — production-сборка
- `npm run build:pages` — сборка под GitHub Pages (с `basePath`)
- `npm run start` — запуск собранного приложения
- `npm run typecheck` — проверка типов
- `npm run lint` — линт
